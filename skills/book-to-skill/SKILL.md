# Book → Skill конвейер

Превращение книги пользователя (PDF/DOC/RTF/DJVU, часто по .lnk-ярлыкам из папки «books to skills») в зарегистрированный Hermes-скилл с дистиллятом «для себя»: Знания-маркеры + Правила для себя (MUST/SHOULD/MUST NOT) + Самодиагностика. Пользователь ведёт серию таких скиллов: категория `self-help`, имена `self-help-<тема>`, архивная копия в `Documents\!LAMA\skills\`.

## Полный конвейер (порядок)

### 1. Разрешить .lnk ярлыки
Ярлыки .lnk хранят путь в ANSI cp1251. `scripts/resolve_lnk.py <файл.lnk>` печатает цель. НЕ использовать PowerShell WScript.Shell для путей с кириллицей — .ps1 читается в ANSI без BOM, кириллица в скрипте искажается (Test-Path возвращает False на существующем файле).

### 2. Извлечь текст по формату
- **PDF**: pymupdf, `doc[i].get_text()`. Если страницы содержат картинки и пустой текст (скан) → шаг OCR.
- **DOC/RTF** (включая RTF с расширением .doc): `scripts/extract_word_docs.py <выходная_папка> <файл1> <файл2>...` — Word COM (win32com, DispatchEx, Visible=False, DisplayAlerts=0, Documents.Open ReadOnly=True, Content.Text, Quit в finally). Это единственный надёжный путь: антиword падает на RTF-подделках («not a Word Document... probably Rich Text Format»), самописные RTF-парсеры оставляют fonttbl и hex-блоки (файл 8.7МБ даёт 7.6М символов «текста»).
- Сравнить дубликаты одной книги в разных форматах (doc vs rtf): по началу файла выбрать более полный (с титулом), второй не дистиллировать.

### 3. OCR скана (русский)
PaddleOCR 3.x требует движок paddlepaddle (часто не установлен) — не углубляться. Рабочий путь — встроенный Windows OCR: `scripts/ocr_ru_batch.ps1 <папка_png> <выход.txt>`.
- **Язык движка принудительно `ru`** (`OcrEngine::TryCreateFromLanguage([Windows.Globalization.Language]::new('ru'))`) — дефолтный en-US движок транслитерирует кириллицу в латиницу (та же болезнь, что RapidOCR без русского).
- Результат писать в UTF-8 файл (`[IO.File]::WriteAllText`), НЕ в консоль — консоль портит юникод.
- Рендер страниц: pymupdf `get_pixmap(dpi=200)`, имена p001.png...

### 4. Найти границы глав
Регэксп по заголовкам (`^Тема N`, `^Глава N`, `^Часть N`) с номерами строк — границы для разбивки. Оглавление в конце файла не путать с телом (фильтровать по номеру строки).

### 5. Параллельная дистилляция (delegate_task)
- Каждый субагент получает ТОЛЬКО свой диапазон строк («обрабатывай строки X-Y, прочитай ВСЕ через read_file offset/limit»), output_schema `{"markdown": string}`, «НЕ выдумывай — только текст файла», «Отвечай НА РУССКОМ».
- Проверенный объём чтения на субагента ≈ 200К символов: плотность файла (chars ÷ строк) определяет длину диапазона (1050 строк × 200 симв/строка = ок; 3850 × 54 = ок). Границы глав — ориентир, рабочие границы — по номерам строк.
- Волны ≤10 параллельных. Пока волна идёт — готовь карту глав следующей книги; вторую волну не запускать до прихода результатов.
- Книга написана для клиницистов/врачей: в КАЖДОЙ задаче волны повторяй ориентацию читателя («обычный человек, самопомощь, не врач; пропускай врачебные технологии») — иначе агенты дистиллируют «что делать врачу с пациентом».
- Единый формат вывода: секции по темам/главам → «Знания-маркеры» + «Правила для себя» (MUST/SHOULD/MUST NOT — проверяемые действия, не пересказ) + «Самодиагностика» (вопросы/чек-листы) + при необходимости «Красные флаги — срочно к врачу».
- Фокус дистилляции менять под запрос пользователя: книга для медсестёр → переработать «для себя»; книга о влиянии → «самозащита». Правило = проверяемое действие, а не «быть вежливым».

### 6. Извлечь результаты субагентов
Файлы-саммари содержат markdown в JSON-обёртке (иногда с ```json-фенсом и преамбулой). Толерантный парсинг: json.loads целиком → фенс → от первого `{` до последнего `}`. Затем `md.replace('\\n', '\n')` (двойное экранирование) и снять фенсы. Проверка полноты: посчитать ожидаемые секции («Тема N» = 20, «Знания-маркеры» ≥ число глав) и остаточные `\n`/`\"`. Порядок файлов-саммари (`subagent-summary-N-<timestamp>.txt` в `cache/delegation/`) лексический = порядок задач диспатча — по нему сопоставляй части книги в смешанных волнах (напр. задачи 0-5 = Изард, 6-9 = Бэрон). Файлы собирать glob'ом с `assert len(paths) == число_задач_волны` — недостающий саммари означает упавшую задачу, не собирать вслепую.
Сразу после извлечения печатать `len()` каждой части и СУММУ — решение «один скилл vs две тематические половины» принимать по сумме ДО сборки единого файла (см. шаг 7), а не после: единый файл-переросток (>100К) всё равно придётся резать и пересобирать заново (проверено: Бурно сначала собран 151К целиком и переделан; Рубинштейн сразу собран двумя половинами).

### 7. Собрать скилл
- Лимит содержимого SKILL.md — 100К символов (валидатор). Выбор схемы по размеру дистиллята:
  - ≤100К → один скилл, весь дистиллят в SKILL.md (основной режим серии).
  - 100–200К → разбить на 2 тематических скилла `self-help-<тема1>` + `self-help-<тема2>` (проверено: Бурно 151К→82+70К, Рубинштейн 174К→91+82К). Граница — по темам глав (метод vs практика сообщества; познание vs личность), не механически 50/50; в шапку каждого скилла добавить строку-ссылку на соседний («…— в скилле self-help-…»). Весь дистиллят остаётся в автозагружаемых SKILL.md без потерь — это предпочтительный вариант, пока пользователь рад множеству скиллов в разделе.
  - ≫200К, либо пользователь хочет ОДИН скилл на книгу → SKILL.md = ядро-маршрутизатор (таблица «жалоба → какой reference») + сквозные принципы, полный дистиллят блоками в `references/lectures-N-M.md` (каждый <100К).
- description ≤60 символов, одно предложение, trigger первым (`Use when user ...`), без маркетинга; иначе skill_manage create отклоняет.
- frontmatter: name/description/version/author/license/platforms/source (путь к PDF-первоисточнику).
- Категория `self-help` для серии самопомощи.
- Регистрация: прямая запись frontmatter+тело в `<hermes>/skills/<категория>/<name>/SKILL.md` (mkdir -p сначала) — `hermes skills list` подхватывает как local/enabled. Для тел ~100К это надёжнее `skill_manage create` (тот капризен на больших телах и батчах). description всё равно ≤60 символов (считая без обрамляющих кавычек), иначе валидатор отклонит. Проверка после записи: `hermes skills list | grep <name>`. Сборку автоматизирует `scripts/make_selfhelp_skill.py`.
- Превышение 100К на 1-5К: итеративные проходы очистки — выкинуть служебные артефакты агентов (ссылки на номера строк `[1234]`, строки «Источник:», преамбулы «Весь материал… прочитан…», длинные дисклеймеры), укоротить длинные H1, убрать строки `---`, хвостовые пробелы, схлопнуть 3+ пустых строки; пересчитывать размер после каждого прохода (обычно 3-6 проходов).

### 8. Синхронизировать архив
`cp -r` папки скилла в `C:\Users\Administrator\Documents\!LAMA\skills\self-help\<name>\` (пользователь держит там архивную копию; сверить `diff -r`). Любая ПОЗДНЯЯ правка зарегистрированного скилла (напр. description оказался >60 и ужат после записи) применяется в `<hermes>/skills/.../SKILL.md` И затем повторно копируется в архив — иначе две копии расходятся, а `diff -r` молчит, пока его не запустишь.

## Скрипты
- `scripts/resolve_lnk.py` — цель .lnk (cp1251 ANSI путь).
- `scripts/extract_word_docs.py` — DOC/RTF → UTF-8 текст через Word COM.
- `scripts/ocr_ru_batch.ps1` — пакетный русский OCR папки PNG → UTF-8 файл.
- `scripts/extract_summaries.py` — файлы-саммари субагентов → объединённый дистиллят (толерантный парсинг JSON/фенсов/преамбул, разэкранирование, схлопывание пустых строк).
- `scripts/make_selfhelp_skill.py` — собрать SKILL.md из дистиллята: frontmatter + прямая запись в Hermes + копия в архив !LAMA.

## Граблі (обобщённые)
- Самописный RTF-парсер = мусор из fonttbl/hex → всегда Word COM для DOC/RTF.
- .ps1 с кириллицей в путях ломается (ANSI-чтение без BOM) → не класть кириллические пути в .ps1-скрипты; для .lnk — бинарный парсинг.
- Windows OCR по умолчанию берёт en-US и транслитерирует кириллицу → принудительно ru.
- Консоль PowerShell портит русский вывод → писать в UTF-8 файл.
- Не верить саммари субагентов на слово: JSON проверять программно, полноту — по числу секций.
- Промежуточные тексты книг хранить в `books to skills/texts/` рядом с исходниками — субагенты читают файлы, а не контекст.
- Заголовки H1 частей в саммари часто называют главы НЕ своего диапазона (реальная нумерация глав в тексте смещена от ожидаемой) — вводную объединённого дистиллята писать без привязки к номерам глав; первые H1 частей заменять на короткие `## Часть N: …`, чтобы не плодить дубли темы книги и не раздувать размер.
- Кажущийся тематический дубль между двумя частями (обе H1 заявляют «гнев/страх») при НЕпересекающихся диапазонах строк — не дубль, а смещение нумерации глав; контент проверять по границам строк, ничего не выбрасывать по совпадению заголовков.
